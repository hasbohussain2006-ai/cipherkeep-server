# 02 — خطة التنفيذ (Roadmap)

للحالة اللحظية التفصيلية، راجع `04_PROGRESS.md`. هذا الملف يوثّق **الخطة الثابتة**.

## Phase 1 — 🟢 مكتملة رسميًا

الهدف كان إثبات صحة المعمارية بأصغر شريحة عمل حقيقية (`codes`, `devices`, Core+DIP، بوت التشفير). **تم بالكامل** — كل بنود `PHASE1_CHECKLIST.md` (22/22) مُثبَتة حيًا. تفاصيل كاملة بـ`04_PROGRESS.md` و`10_CHANGELOG.md`، شاملة مراجعة أمنية إضافية (R1, C1, H1-H6, L1-L2, #19) نُفِّذت أثناء دورة الإغلاق نفسها.

## Phase 2 — قيد البدء

**الترتيب المعتمَد (لا يجوز تجاوزه):**

### المهمة 1 (جارية الآن): ترحيل أوامر الإدارة المتبقية لـSupabase
- `/admin/list` — يحتاج قدرة استعلام تفاصيل كاملة (لا فقط رموز الأكواد)
- `/admin/revoke` — إكمال الترحيل (المسار الإداري لـSupabase موجود جزئيًا فعلًا عبر C1، يبقى حذف الاعتماد على `licenses.json`)
- `/admin/pause_all` — نفس الملاحظة
- `/admin/extend` — غير موصولة بـSupabase إطلاقًا بعد؛ تحتاج `Core.admin_force_extend()` جديدة (تناظر `admin_force_revoke`)
- **بعد نجاح الترحيل الكامل والتحقق الحي:** حذف `licenses.json` نهائيًا — Supabase يصبح Single Source of Truth بلا استثناء

### المهمة 2: نظام صلاحيات المشرفين (Owner → Moderators → Customers)
- المالك (Owner) فقط يضيف/يعطّل/يحذف المشرفين (Telegram ID أو آلية تُحدَّد)
- المشرفون ينشئون ويفعّلون الأكواد للعملاء — لا الـOwner مباشرة
- البنية جاهزة أصلًا بـCore/DAL (`ModeratorRepository`, `revoke_code`/`extend_code` بفحص ملكية) — المتبقي: **بوت الإدارة نفسه (Telegram Adapter)**، لم يُكتب بعد
- **صريح: لا نظام باقات/تسعير بهذي المهمة** (معلَّق، `06_TODO.md`)

### المهمة 3 (بعد الأولى والثانية): مراجعة أمن سيبراني شاملة
بعد اكتمال البوتات وربطها النهائي.

## خارج نطاق Phase 2 الحالي صراحة

**لا لوحة ويب، لا Dashboard، لا API عام، لا بوت دعم/عملاء** — كل هذا Backlog محفوظ (`06_TODO.md`)، لا يبدأ إلا بطلب صريح منفصل.

## بروتوكول العمل

كل خطوة تُنفَّذ فقط بعد إذن صريح ("ابدأ") بنفس المحادثة. القرارات المعمارية أو تعديلات العقود تُعرَض للموافقة قبل التنفيذ (`03_RULES.md`).
