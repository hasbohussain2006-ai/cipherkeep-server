# 10 — سجل التغييرات (Changelog)

*ملاحظة: التواريخ الدقيقة لكل قرار غير مسجَّلة بدقة كاملة بمصدر المحادثات الأصلي. الترتيب هنا زمني حسب تسلسل الإنجاز الفعلي، لا حسب تواريخ تقويمية. يُحدَّث هذا الملف بنهاية كل خطوة أو مرحلة (`03_RULES.md` #10).*

## المعمارية

- تصميم نموذج الطبقات الأربع (البوتات → Core → DAL → Supabase) واعتماده
- حسم مبدأ DIP والسبب النهائي (قابلية الاختبار)
- تصميم واعتماد `ServerModeService` كخدمة مجال منفصلة (بدل تضخيم Core)
- تصميم واعتماد سياسة Transaction/Concurrency (`ck_claim_device_slot`)
- **اعتماد Architecture Freeze** — `01_ARCHITECTURE.md` أصبح مُجمَّدًا رسميًا

## Roadmap Phase 1 — التنفيذ

- **الخطوة 1:** مخطط Supabase (`codes`, `devices`, `pgcrypto`) — منفَّذ ومثبَت حيًا
- **الخطوة 2:** `CipherKeepCore` + الواجهات المجرَّدة + Fakes + اختبارات وحدة — منفَّذ ومختبَر محليًا (11 اختبار)
- **الخطوة 3:** Data Access Layer ضد Supabase حقيقية — منفَّذ، مختبَر محليًا (9 اختبارات محاكاة) ومثبَت حيًا (إنشاء/تحقق/فك تشفير/حد أجهزة/تزامن حقيقي عبر Threading)
- **الخطوة 4 (جزئية):** ترحيل `/verify` + `/admin/create` — منفَّذ، مختبَر محليًا (9 اختبارات Flask)، بانتظار نتيجة الإثبات الحي (`live_proof_supabase.py` جاهزة ومُرسَلة)
- **الخطوة 5:** إصلاح بوت التشفير (تدفق أزرار تجربة/كاملة → عدد أجهزة → مدة، بدل قيم ثابتة) — منفَّذ، فحص صياغة فقط
- **الخطوة 6:** فحص صحة عند الإقلاع + إشعار تيليجرام عند فشل/غياب إعداد Supabase — منفَّذ، فحص صياغة فقط
- **الخطوة 7:** أداة إثبات حي شامل (`full_lifecycle_proof.py`) — تحاكي إعادة نشر فعلية عبر إعادة تحميل الوحدة — منفَّذة، لم تُشغَّل بعد
- تصحيح عقد أثناء التنفيذ: إضافة `is_new_device` ثم `label` لـ`VerifyResult`، وإغلاق العقد صراحة بعدها

## تدقيق ما بعد الرفع لهذا الـProject (Post-Upload Audit)

- اكتُشف أن نقل ملفات المشروع لبيئة الـProject تسبَّب بفقدان هيكل المجلدات الأصلي (`cipherkeep_core/`, `cipherkeep_dal/`, `tests/`) — كل الملفات ظهرت مسطَّحة بمستوى واحد، مع تصادم أسماء ناتج عنه لواحق تلقائية (`license_server-1.py`, `core-1.py`, `__init__-6.py`, `test_core-1.py`)
- اكتُشف أن ثلاثة ملفات (`core.py`, `fakes.py`, وملفَي بوت التشفير `encryptor.py`/`encryption_bot.py`) كانت غائبة كليًا من نسخة الـProject عند الفحص الأول
- أُعيدت الملفات الثلاثة المفقودة من مصدرها الأصلي، وتأكَّد تطابق محتواها الكامل مع كل استيراد/إشارة موجودة بالملفات الأخرى (تحقُّق حرفي لثوابت `MAGIC`/`HEADER_FMT` بين `crypto.py` و`encryptor.py`)
- أُنشئ `PHASE1_CHECKLIST.md` كمرجع رسمي وحيد لتحديد شروط إغلاق Phase 1 (22 بندًا)
- أُنشئ `PHASE2_PREPARATION.md` كملف تحضيري بحت — لا يتضمّن أي بدء تنفيذ فعلي لـPhase 2
- **لم يتغيّر أي رمز حالة اختبار (🟠/🟡/🟢) نتيجة لهذا الاسترجاع وحده** — مشاكل التسمية وهيكل المجلدات اعتُبرت أثرًا لطريقة الرفع، لا فجوة بالمشروع نفسه، بقرار صريح من المستخدم
- Phase 1 **لا تزال مفتوحة** — 5 بنود تحتاج تشغيلًا فعليًا و4 بنود تحتاج إثباتًا حيًا، موثَّقة بالكامل بـ`PHASE1_CHECKLIST.md`
