# 01 — المعمارية (Core Architecture)

**الحالة: مُجمَّدة جزئيًا.** المبادئ الأساسية (§1-8) لا تزال Architecture Freeze كما كانت. الأقسام 9-11 أدناه إضافات معتمَدة أثناء المراجعة الأمنية لـPhase 1 (موثَّقة بالكامل بـ`05_DECISIONS.md`)، ولا تُعتبَر "كسرًا" للتجميد بل امتدادًا معتمَدًا بنفس روحه.

## 1) نموذج الطبقات الأربع

```
البوتات (+ لوحة ويب/API مستقبلًا)
        ↓ يستدعي فقط
CipherKeep Core  ← كل منطق الأعمال
        ↓ يستدعي فقط
Data Access Layer  ← وصول قاعدة بيانات فقط
        ↓
Supabase (التخزين الدائم)
```

**قاعدة صارمة:** كل طبقة تستدعي فقط الطبقة التي تحتها مباشرة. البوت ممنوع يوصل DAL مباشرة.

## 2) مسؤوليات كل طبقة

| الطبقة | تحتوي | ممنوع عليها |
|---|---|---|
| **البوتات/الواجهات** | استقبال الطلب، تحليل الهوية الخاصة بقناتها، استدعاء Core، عرض النتيجة | أي قرار عمل، أي منطق تحقق أو تشفير |
| **CipherKeep Core** | كل منطق الأعمال | استيراد تيليجرام، SQL خام، معرفة قناة الاتصال |
| **Data Access Layer** | استعلامات Supabase فقط | أي قرار عمل أو قاعدة صلاحية |
| **Supabase** | التخزين الدائم | — |

## 3) مبدأ عكس التبعية (Dependency Inversion)

Core يعتمد على واجهات مجرَّدة (`typing.Protocol`، بلا `ABC`) — لا يعرف Supabase مباشرة. السبب المعتمد: قابلية الاختبار (Fakes بالذاكرة). لا `LicenseRepository` منفصلة — الكود هو الترخيص نفسه.

## 4) خدمات المجال (Domain Services)

عمليات مركّبة (فك تشفير وضع السيرفر) تُبنى كخدمة منفصلة (`ServerModeService`) بالتركيب فوق Core، لا كدالة مضافة على `CipherKeepCore` مباشرة. مثال إضافي معتمَد (§9 أدناه): فصل التحقق عن الحجز عبر دالتين جديدتين على Core نفسه (لا خدمة منفصلة) — قرار موثَّق أدناه لأنه ليس "عملية مركّبة جديدة" بل تفكيك عملية قائمة لبنتين أصغر قابلتين لإعادة الاستخدام.

## 5) سياسة Transaction / Concurrency

الذرّية الحقيقية تحت التزامن (حجز سلوت جهاز) تُحَل حصرًا داخل محرك التخزين (`ck_claim_device_slot`، قفل `FOR UPDATE`)، لا بكود Python. **تحديث معتمَد (إصلاح R1):** استدعاء `claim_device_slot` (عبر `register_device()`) لا يزال ذريًا بمعزل تام عن **متى** يُستدعى — تأجيل توقيت الاستدعاء لبعد نجاح فك التشفير لا يفكّك هذي الذرية إطلاقًا (تفصيل كامل بـ`05_DECISIONS.md`).

**نافذة سباق متبقية موثَّقة بوعي:** فحص الصلاحية داخل `register_device()` (قراءة مستقلة قبل الحجز) ليس ذريًا مع الحجز نفسه على مستوى SQL — تخفيف حقيقي (يضيّق النافذة لفارق قراءتين متتاليتين)، لا إغلاق كامل. الإغلاق الكامل (دمج الفحصين بقفل SQL واحد) مؤجَّل لـPhase 2 عمدًا.

## 6) بصمة الجهاز (Device Fingerprint)

تُعامَل دائمًا كـ"إشارة بأفضل جهد" — ممنوع معماريًا ربط أي إجراء لا رجعة فيه بها منفردة. **ملاحظة أمنية موثَّقة:** هذا يعني أن `max_devices` عمليًا "حاجز أدب" لا حاجز تقني صارم على أندرويد/Termux (حذف ملف بصمة واحد يولّد هوية جديدة) — مخاطرة مقبولة موثَّقة، غير محلولة.

## 7) معيار إدراج الحقول المبكر بقاعدة البيانات

لا إدراج حقل/علاقة/جدول إلا بتحقق: (أ) فقدان معلومة لا رجعة فيه، أو (ب) تكلفة تعديل كاسرة لاحقًا.

## 8) حل مشكلة فقدان البيانات

Supabase (Postgres) = المصدر الوحيد للحقيقة لكل حالة دائمة. **حالة حالية (Phase 2 قيد التنفيذ):** `/verify` و`/admin/create` مُرحَّلان بالكامل. `/admin/list`, `/admin/revoke`, `/admin/pause_all`, `/admin/extend` — الأخيران وصلا لمسار Supabase جزئيًا عبر مسار إداري إضافي (C1، §10 أدناه)، لكن `licenses.json` المحلي لا يزال موجودًا بالتوازي حتى اكتمال الترحيل الكامل (مهمة Phase 2 الأولى الجارية).

## 9) إصلاح R1 — فصل تحقق الصلاحية عن حجز الجهاز (معتمَد، Composition over Modification)

**المشكلة الأصلية:** `verify_code()` كانت تحجز سلوت الجهاز **قبل** أي تحقق من صحة مادة التشفير — يمكّن استنزاف السلوتات بمعرفة نص الكود وحده، بلا حاجة لمفتاح صحيح.

**الحل المعتمَد:** إضافة (لا تعديل) دالتين عامتين جديدتين على `CipherKeepCore`:
- `check_code_validity(code, now=None) -> CodeValidityResult` — تحقق صلاحية فقط، بلا حجز
- `register_device(code, device_fingerprint, now=None) -> DeviceRegistrationResult` — حجز فقط، تُستدعى بعد نجاح فك تشفير

كلاهما يستدعيان دالة خاصة مشتركة `_resolve_valid_record()` (منع Duplicate Logic، نفس نمط `_check_ownership()` الموجود مسبقًا).

**`verify_code()` الأصلية بلا أي تغيير بالتوقيع أو السلوك الخارجي** — تبقى تخدم أي مستهلك يريد "تحقق+حجز" كخطوة واحدة (`test_core.py`, `concurrency_test_supabase.py`).

**`ServerModeService.verify_and_decrypt()`** هي المستهلك الوحيد الذي يستخدم المسار الجديد: `check_code_validity()` → `decrypt_blob()` → `register_device()` (فقط عند نجاح فك التشفير).

**قرار Public API:** كلا الدالتين الجديدتين **Public**، لا Private — مبرَّر بمبادئ Encapsulation (ليستا تفاصيل تنفيذ داخلية، بل نقطة تركيب مقصودة)، Minimal Public Surface (ضروريتان لمستهلك حقيقي قائم)، Future Extensibility (نمط قابل لإعادة الاستخدام لخدمات مجال مستقبلية كـ`/admin/decrypt`)، Compatibility (لا يمس أي مستهلك قائم).

## 10) إصلاح C1 — مسار إداري منفصل لتجاوز الملكية (Kill Switch)

**المشكلة:** `/admin/revoke`/`/admin/pause_all` لا يؤثران على أكواد Supabase؛ `Core.revoke_code()` القائمة تفرض فحص ملكية (`moderator_id`) يرفض دائمًا أكواد Phase 1 (`moderator_id=None`).

**الحل المعتمَد:** دالتان جديدتان تمامًا على Core، **لا تعديل** على `revoke_code()`/`extend_code()` القائمتين:
- `admin_force_revoke(code) -> RevokeResult` — تتجاوز فحص الملكية عمدًا، مبرَّرة بكون `ADMIN_TOKEN` صلاحية أعلى بنيويًا من أي `moderator_id` فردي
- `admin_pause_all() -> int` — تعتمد على واجهة مجرَّدة جديدة `CodeQueryRepository` (منفصلة عن `CodeRepository` عمدًا — فصل مسؤوليات: استعلام جماعي إداري ≠ عملية Aggregate فردية)

**تنفيذ `CodeQueryRepository.list_all_codes()`** عبر REST القياسي التلقائي لـPostgREST (`GET /rest/v1/codes?select=code`) — **بلا أي RPC جديدة أو تعديل مخطط قاعدة بيانات**.

## 11) إصلاح #19 — معالجة موحَّدة لفشل الاتصال بـSupabase

**اكتُشف أثناء الاختبار الحي:** استثناءات `SupabaseRequestError`/`requests.exceptions.RequestException` كانت تتسرّب خامًا لأي طلب فعلي فشل بالاتصال (لا فشل الإقلاع فقط، ذاك كان مُعالَجًا مسبقًا).

**الحل:** معالج Flask عام (`@app.errorhandler`) يغطي **كل** نقاط الدخول تلقائيًا، يرجع `{"ok": false, "reason": "backend_unavailable"}` بـ500، بلا أي Stack Trace متسرّب.

**اكتشاف ثانٍ حرج بنفس الجولة:** `except RuntimeError` عام بـ`admin_pause_all()` كان يبتلع `SupabaseRequestError` صامتًا (لأنها وريثة `RuntimeError`)، يرجع نجاحًا وهميًا. **الحل:** استثناء جديد `RepositoryNotConfigured(Exception)` — **عمدًا لا يرث من `RuntimeError`** — لمنع هذا التصادم نهائيًا.
