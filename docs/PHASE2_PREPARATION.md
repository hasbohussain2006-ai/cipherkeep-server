# PHASE 2 — تجهيز وبدء فعلي

**تحديث حالة:** Phase 1 مغلَقة رسميًا (`PHASE1_CHECKLIST.md` 22/22). Phase 2 **بدأت فعليًا** بالمهمة الأولى أدناه — هذا الملف لم يعد "تحضيريًا بحتًا" كنسخته الأصلية، بل خطة عمل فعلية معتمَدة.

## الترتيب المعتمَد (مُحدَّث — يختلف عن الترتيب الأصلي الموثَّق سابقًا)

**⚠️ تصحيح مهم:** النسخة الأصلية من هذا الملف وصفت "بوت الإدارة + نظام صلاحيات المشرفين" كالمهمة الأولى مباشرة. **القرار الفعلي المعتمَد لاحقًا (موثَّق بـ`05_DECISIONS.md`) غيّر هذا الترتيب**: اكتُشف أثناء اختبارات ما بعد إغلاق Phase 1 أن `/admin/list`/`/admin/revoke`/`/admin/pause_all`/`/admin/extend` لا تزال جزئيًا أو كليًا على `licenses.json` — وهذا يجب حسمه **قبل** بناء نظام مشرفين فوق مصدر بيانات غير موحَّد بعد.

### المهمة 1 (جارية الآن): ترحيل أوامر الإدارة بالكامل لـSupabase

| النقطة | الحالة الحالية | المطلوب |
|---|---|---|
| `/admin/list` | `licenses.json` فقط | قدرة استعلام تفاصيل كاملة من Supabase |
| `/admin/revoke` | مزدوج (محلي + Supabase عبر C1) | إزالة الاعتماد على `licenses.json` بعد التحقق الحي |
| `/admin/pause_all` | مزدوج (محلي + Supabase عبر C1) | نفس الملاحظة |
| `/admin/extend` | `licenses.json` فقط، **بلا أي اتصال Supabase** | `Core.admin_force_extend()` جديدة (تناظر `admin_force_revoke`) |

**بعد نجاح الترحيل الكامل + تحقق حي:** حذف `licenses.json` نهائيًا. Supabase = Single Source of Truth بلا استثناء، بلا مصدرين متوازيين.

### المهمة 2 (بعد الأولى): نظام صلاحيات المشرفين

**النطاق (Owner → Moderators → Customers):**
- **Owner** (أنت): الوحيد الذي يضيف/يعطّل/يحذف المشرفين
- **Moderators**: ينشئون ويفعّلون الأكواد للعملاء — لا Owner مباشرة
- **Customers**: يستلمون الأكواد من المشرفين فقط

**الجاهز أصلًا (كود Phase 1، بانتظار التفعيل):**
- `ModeratorRepository`, `Moderator` model
- `Core.register_moderator()`, `Core.resolve_moderator()`
- `Core.revoke_code()`/`extend_code()` بفحص ملكية (`moderator_id`)
- عمود `codes.moderator_id` (بالمخطط، غير مُطبَّق حيًا بعد)

**المتبقي الفعلي الوحيد:** **بوت الإدارة نفسه (Telegram Adapter)** — لم يُكتب حرف واحد منه بعد.
