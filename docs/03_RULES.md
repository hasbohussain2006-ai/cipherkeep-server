# 03 — القواعد الملزمة (Rules)

هذي القواعد ملزمة لأي محادثة تطوير مستقبلية على هذا المشروع، بلا استثناء.

## 1) لا كود بدون إذن صريح
لا تُكتب أو تُعدَّل أي أسطر كود إلا بعد كلمة **"ابدأ"** صريحة بنفس المحادثة. الاتفاق على تصميم ليس إذنًا للتنفيذ.

## 2) Architecture Freeze (مُحدَّثة)
`01_ARCHITECTURE.md` §1-8 مُجمَّدة. §9-11 (إضافات المراجعة الأمنية) امتداد معتمَد، لا كسر للتجميد. أي تعديل معماري جديد يظهر أثناء التنفيذ:
- **يُوقَف التنفيذ فورًا.**
- يُعرَض السبب الهندسي + الخيارات + توصية واحدة واضحة.
- لا يُنفَّذ إلا بموافقة صريحة.
- بعد الاعتماد، يُحدَّث `01_ARCHITECTURE.md` و`05_DECISIONS.md` معًا — لا يبقى قرارًا شفهيًا بمحادثة.

## 3) تعديل العقود (Contracts)
أي عقد قائم لا يُعدَّل إلا بموافقة صريحة مسبقة. `VerifyResult` **مُغلَق نهائيًا بلا أي استثناء** — أي حاجة جديدة تُبنى كنوع مستقل جديد (نمط معتمَد فعليًا: `CodeValidityResult`, `DeviceRegistrationResult`)، لا بتوسيع عقد قائم.

## 4) لا توسيع نطاق أثناء التنفيذ
كل خطوة Roadmap تُنفَّذ بنطاقها المحدد فقط. أي ميزة إضافية → `06_TODO.md`.

## 5) اختبار فعلي حقيقي إلزامي
لا تسليم بدون تشغيل فعلي. عند غياب القدرة على اختبار حي: يُبنى أقصى اختبار ممكن محليًا، يُصرَّح بوضوح تام بما اختُبر فعليًا مقابل ما يحتاج تأكيدًا حيًا، تُبنى أداة إثبات حي يشغّلها المستخدم بنفسه.

**قاعدة إضافية معتمَدة (درس فعلي من دورة إغلاق Phase 1):** **الدليل الحرفي (رد API فعلي، سطر Log كامل) هو الوحيد المقبول لإثبات حالة حية — وصف نصي لما "حدث" ("تم التشغيل بنجاح"، "الاختبار نجح") بلا الناتج الحرفي المرفق **لا يُعتبَر إثباتًا كافيًا**، مهما بدا تفصيليًا. هذا ليس شكًا بنية المستخدم — هو التزام بنفس المعيار الذي طبَّقناه على الذكاء الاصطناعي نفسه طوال هذي المحادثة (رفض قبول "الملف بريء" كنتيجة نهائية دون تتبّع الدليل حتى مصدره الفعلي).

## 6) صراحة كاملة، بلا تجميل
أي قيد تقني، تعقيد حقيقي، أو حد فعلي بالأداة يُشرَح صراحة بدل إخفائه.

## 7) منع حلقة "تخطيط بدون تنفيذ"
نطاق أي خطوة يُحدَّد بوضوح قبل أي نقاش تصميم إضافي. أي فكرة جديدة أثناء النقاش → Backlog فورًا.

## 8) لا اختراع معلومات
لا تُفترَض معلومة غير موجودة صراحة. عند وجود قرار غير محسوم أو تناقض → **توقف واعرضه للمستخدم قبل المتابعة.**

**تطبيق موسَّع (درس فعلي):** هذا يشمل أيضًا عدم الافتراض بأن استثناء تشخيصي مؤقت (`raise`/`print`) وضعناه **بعد** طلب سابق لا يزال المصدر الوحيد للحقيقة — لازم إعادة تقييم الأدلة بترتيبها الزمني الفعلي عند ظهور أدلة جديدة تتعارض ظاهريًا مع أدلة أقدم.

## 9) هذي الوثائق هي المصدر الوحيد للحقيقة
لا تعتمد أي محادثة تطوير مستقبلية على سجل محادثات قديمة. كل قرار معتمَد موجود هنا.

## 10) تحديث الوثائق مع نهاية كل مرحلة
عند إنهاء أي خطوة أو مرحلة: تُحدَّث `04_PROGRESS.md` و`10_CHANGELOG.md` إلزاميًا، أي قرار جديد → `05_DECISIONS.md`، أي عقد جديد/معدَّل → `07_API.md`.

## 11) Feature Freeze (قاعدة جديدة معتمَدة)
عند الاقتراب من إغلاق مرحلة (Phase) رسميًا، يُعلَن **Feature Freeze** صراحة من المستخدم: من تلك اللحظة، **لا تُقتَرح أو تُنفَّذ أي تحسينات/اكتشافات/Refactoring جديدة** — كل ما يظهر يُسجَّل بـBacklog المرحلة التالية فقط، ولا يؤخر الإغلاق. الاستثناء الوحيد: خطأ حقيقي يمنع إغلاق بند موجود أصلًا بالـChecklist (مثل اكتشاف #19 أثناء اختباره الحي) — هذا يُصلَح فورًا ضمن نفس المرحلة لأنه ليس "تحسينًا جديدًا" بل شرط إغلاق أصلي لم يكن معروفًا كناقص.

## 12) دليل توجيه محادثات مستقبلية
تفاصيل سلوك أي محادثة Claude جديدة موثَّقة بـ`09_AI_GUIDELINES.md`.
